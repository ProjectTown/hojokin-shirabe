# 補助金しらべ

設備投資・IT導入に使える補助金を、**地域・業種・締切で横並びに比較できる**静的サイト。

- 出典: デジタル庁「Jグランツ」公開API（無料・認証不要）
- 掲載範囲: カテゴリ「設備整備・IT導入をしたい」で募集中の 92件
- 生成ページ数: 1,199

## 運用方針

| 項目 | 方針 |
|---|---|
| 費用 | **0円**。有料契約・ドメイン購入・広告出稿・有料APIは使わない |
| 個人情報 | **一切収集しない**。入力欄・会員登録・Cookie追跡なし |
| 問い合わせ | **窓口を設けない**。制度の質問は各公式窓口へ誘導 |
| 収益化 | **当面行わない**。まず需要検証（[METRICS.md](METRICS.md)） |
| 受給可否 | **判定しない**。公開データの整理・表示に徹する |
| 更新 | GitHub Actions で毎日自動。手作業なし |

## 既存の競合との違い

「同じ機能しかないなら作らない」という判断基準に対する回答。

| | Jグランツ公式 | 民間ポータル | 本サイト |
|---|---|---|---|
| 掲載形式 | 制度ごとに自由記述 | 記事・一覧 | **全件を同じ項目に整形して横並び比較** |
| 締切の扱い | 日付のみ | 一覧表示 | **残り日数を全件に表示し、締切順が既定** |
| 絞り込み条件 | URLに残らない | 会員登録を要求する例が多い | **条件がそのままURLになり共有・ブックマーク可** |
| 会員登録 | 申請には必要 | 要求されることが多い | **不要** |
| 個人情報 | 申請のため収集 | 収集する例が多い | **入力欄そのものが無い** |
| 広告 | なし | あり | **なし** |

中核の差別化は**「比較可能性」**。公式データは制度ごとに書式がばらばらで並べて比べられない。
それを同一フォーマットに正規化して初めて「どれが自分に近いか」が判断できる。

この差が実際に使われるかを30日間の実測で検証する。使われなければ中止する。

## 構成

```
scripts/fetch-category.mjs   1カテゴリ分のみ取得（1検索100件 / 1実行110リクエストの上限を強制）
scripts/normalize.mjs        整形して data/subsidies.json を生成
src/pages/
  index.astro                トップ
  search/                    条件検索・結果・0件ページ
  s/[id].astro               補助金の詳細（92）
  go/[id].astro              公式サイトへの中継（92・noindex）
  area/[pref].astro          都道府県別（47）
  industry/[slug].astro      業種別（20）
  find/[area]/[industry]/    地域×業種（940）
  about.astro                免責事項・データの出典
```

## 使い方

```bash
npm install
npm run data     # データ取得（対象カテゴリのみ）＋整形
npm run build    # dist/ に静的サイトを生成
npm run dev      # 開発サーバー
```

## 運用方法

日常の操作は不要。以下が自動で回る。

| いつ | 何が起きるか | どこで |
|---|---|---|
| 毎日 06:00 (JST) | Jグランツから対象カテゴリのデータを取り直す | GitHub Actions |
| 取得後 | 変化があれば `data/` をコミット | GitHub Actions |
| コミット後 | サイトを再ビルドして公開 | Cloudflare Pages |

### 取得に失敗したとき

自動で以下のように退避する。**サイトが空になったり落ちたりしない。**

1. API障害・仕様変更などで取得に失敗 → 直前に正常取得したデータをそのまま使い続ける
2. 取得件数が前回の半分未満に急減 → 異常とみなし、やはり既存データを維持する
3. 最終取得から3日以上経過 → 全ページの最上部に警告帯を出し、内容が古い可能性を利用者に伝える

締切日を過ぎた制度は、毎回のビルド時に「受付終了」と表示され、一覧の末尾にまとめられる。

### 状態の確認

- 更新の成否: GitHubリポジトリの **Actions** タブ
- 公開の成否: Cloudflare ダッシュボードの **Workers & Pages**
- データの鮮度: サイト下部に「データ取得日」を常時表示

## 停止方法

| やりたいこと | 手順 | 効果 |
|---|---|---|
| **自動更新だけ止める** | GitHub → Actions →「補助金データの日次更新」→ `···` → Disable workflow | サイトは公開されたまま。データが固定される |
| **サイトを非公開にする** | Cloudflare → Workers & Pages → プロジェクト → Settings → Delete project | URLが消える。コードはGitHubに残る |
| **完全に止める** | 上の2つを実施し、GitHubリポジトリを Archive または Delete | すべて停止 |
| **一時的に更新を止める** | `.github/workflows/update-data.yml` の `schedule:` 行をコメントアウトしてコミット | 手動実行のみ可能になる |

いずれも課金は発生しない。無料枠のみで動いているため、放置してもコストは増えない。

## 無料枠の範囲

| サービス | 無料枠 | 本サイトの使用量 |
|---|---|---|
| Cloudflare Pages | 月500ビルド / 帯域無制限 | 月約30ビルド |
| GitHub Actions | publicリポジトリは無料 | 1日1回・数分 |
| Jグランツ API | 無料・認証不要 | 1日あたり最大110リクエスト（上限をコードで強制） |

有料プラン・カード登録・独自ドメインは使用していない。

## データ取得の制限

`scripts/fetch-category.mjs` に上限をハードコードしている。

- `MAX_PER_SEARCH = 100` — 1回の検索で扱う最大件数
- `MAX_REQUESTS = 110` — 1回の実行で送信するリクエスト総数（超えたら中断）
- `CONCURRENCY = 3` — 公共APIへの同時接続数

対象カテゴリは `CATEGORY` 環境変数で切り替える。既定は「設備整備・IT導入をしたい」。
全カテゴリの一括取得は行わない。
